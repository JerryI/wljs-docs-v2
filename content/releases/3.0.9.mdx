## Rows, Columns, Grids, and Tables
We significantly improved support for the standard symbols used to format lists and tables. For `Grid`, `Row`, and `Column`, the `Dividers`, `Spacings`, `Alignment`, `ImageSize`, and `BaselinePosition` options are now supported. For `TableForm`, `TableAlignments`, `TableHeadings`, and `TableSpacing` are supported as well. Here are a few examples:

## Improved support for packed arrays
We improved how packed arrays are stored and transferred from the Wolfram Kernel to the frontend. During initial evaluation, `Graphics` and `Image` expressions are usually serialized as `"ExpressionJSON"` and reinterpreted in the frontend; subsequent updates use binary WXF. That initial pass was inefficient because numeric and packed arrays were serialized as plain lists by default, increasing payload sizes by 10-100 times. We patched the standard JSON serializer so packed and numeric arrays are sent as base64-encoded WXF strings. This matters especially for data structures such as `Image` and `Graphics3D` objects with many vertices.

<WLJSWrapper><wljs-editor display="codemirror" type="Input" editable="true"  >{`ComplexPlot3D[(*FB[*)(((*SpB[*)Power[Sin[z](*|*),(*|*)3](*]SpB*))(*,*)/(*,*)((*SpB[*)Power[(z+1)(*|*),(*|*)4](*]SpB*)))(*]FB*), {z, -5 - 5 I, 5 + 5 I}]`}</wljs-editor></WLJSWrapper>

<WLJSWrapper><wljs-editor display="codemirror" type="Output"  >{`(*VB[*)(FrontEndRef["22af5701-3668-44e0-a384-d673c15f2f5d"])(*,*)(*"1:eJxTTMoPSmNkYGAoZgESHvk5KRCeEJBwK8rPK3HNS3GtSE0uLUlMykkNVgEKGxklppmaGxjqGpuZWeiamKQa6CYaW5joppiZGycbmqYZpZmmAABzwhUT"*)(*]VB*)`}</wljs-editor></WLJSWrapper>

As before, the data is also compressed with gzip. This should reduce file size, memory use, and CPU usage.

## Association keys for frontend symbols
Frontend symbols that are associations now support key access. Previously, you could do this:

<WLJSWrapper><wljs-editor display="codemirror" type="Input" editable="true"  >{`h = {1,2}; 
	TextView[h[[1]]//Offload]`}</wljs-editor></WLJSWrapper>

<WLJSWrapper><wljs-editor display="codemirror" type="Input" editable="true"  >{`a = <|"a"->1, "b"->0.3|>;
	TextView[a["a"]//Offload]
	TextView[a["b"]//Offload]`}</wljs-editor></WLJSWrapper>

Now `a["key"]` works when `a` is an `Association`. Try it yourself!
