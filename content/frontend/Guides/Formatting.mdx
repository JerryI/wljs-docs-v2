Formatting in WLJS is not limited to text. Numbers, formulas, lists, tables,
graphics, controls, and even complete interfaces are all Wolfram Language
expressions, and the same formatting functions can be composed around them.

If you are coming from Python or Julia, it helps to read the following examples
with three small syntax rules in mind:

- function arguments use square brackets: `Style[expr, Red]`
- lists use braces: `{a, b, c}`
- options are rules: `Background -> Yellow`
- `name = value` assigns a value, and a final semicolon suppresses its output

Wolfram Language also supports postfix notation. These two expressions are
equivalent:

<WLJSWrapper>
<div className="code-input"/>
<wljs-editor display="codemirror" type="Input" editable="true" lazy="true">{`TraditionalForm[expr]  (* equivalent to expr // TraditionalForm *)`}</wljs-editor>
</WLJSWrapper>

Prefix notation is common when several wrappers are composed:
`function @ expr` is equivalent to `function[expr]`.

We shall start with common display tasks, then explain the WLJS-specific
behavior that makes formatted output editable and reusable.

you should use for computation. A reliable pattern is to keep raw data in one

## Formatting numbers

`1/3` is exact, while `N[1/3]` produces a machine-precision approximation.

### Convert to text only when you need text

`NumberForm` is intended for presentation. If a formatted value must become
part of a plain string—for example, for export or a text-only API—use
`ToString` explicitly:

<WLJSWrapper>
<div className="code-input"/>
<wljs-editor display="codemirror" type="Input" editable="true" lazy="true">{`formatted = ToString[NumberForm[1.35356, {4, 1}]]`}</wljs-editor>
</WLJSWrapper>

<WLJSWrapper>
<wljs-editor display="codemirror" type="Output" lazy="true">{`"1.4"`}</wljs-editor>
</WLJSWrapper>


<WLJSWrapper>
<div className="code-input"/>
<wljs-editor display="codemirror" type="Input" editable="true" lazy="true">{`"measurement = " <> formatted`}</wljs-editor>
</WLJSWrapper>

<WLJSWrapper>
<wljs-editor display="codemirror" type="Output" lazy="true">{`"measurement = 1.4"`}</wljs-editor>
</WLJSWrapper>

Here `<>` joins strings. After `ToString`, the result is text rather than a
number, so do not convert values earlier than necessary.

<WLJSWrapper>
<div className="code-input"/>
<wljs-editor display="codemirror" type="Input" editable="true" lazy="true">{`raw = 1.35356;
	raw^2`}</wljs-editor>
</WLJSWrapper>

<WLJSWrapper>
<wljs-editor display="codemirror" type="Output" encoded="true" lazy="true">{`1.8321246736000003%60`}</wljs-editor>
</WLJSWrapper>

## Output forms

An output form answers a different question from `Style` or `Grid`: it chooses
the representation used to display an expression.

### `StandardForm`: normal WLJS output

[`StandardForm`](./../Formatting/StandardForm) is the default form for ordinary
Wolfram Language output cells. In WLJS it is implemented as decorated
[`InputForm`](./../Formatting/InputForm): comments carry visual metadata for
fractions, grids, and other structures, while the remaining text is still valid
Wolfram Language input.

For example, a visually typeset fraction remains based on the plain expression
`(1)/(2)`. This is why WLJS notebook code works well with text editors, Git, and
LLM tools. See [Math typesetting and shortcuts](./../Overview#math-typesetting-and-shortcuts)
for the editor-side details.

You rarely need to write `StandardForm` explicitly in a normal output cell. It
is useful when an expression is being inserted into a cell type that normally
uses another form:

<WLJSWrapper>
<div className="code-input"/>
<wljs-editor display="codemirror" type="Input" editable="true" lazy="true">{`expr = Panel[1/2];
	expr
	StandardForm[expr]`}</wljs-editor>
</WLJSWrapper>

### `WLXForm`: slides, Markdown, and WLX

[`WLXForm`](./../Formatting/WLXForm) is the default representation used when
Wolfram expressions are embedded in [slides](./../Cell-types/Slide),
[Markdown](./../Cell-types/Markdown), and [WLX](./../Cell-types/WLX) cells.
This is distinct from the `StandardForm` used by ordinary output cells.

Most users only need to remember the practical consequence: if an expression
looks different when inserted into a slide or WLX component, wrap it in
`StandardForm` to request the ordinary output-cell representation.

<WLJSWrapper>
<div className="code-input"/>
<wljs-editor display="codemirror" type="Input" editable="true" lazy="true">{`WLXPanel = StandardForm @ Deploy @ Panel[Plot[x, {x,0,1}]];`}</wljs-editor>
</WLJSWrapper>

<WLJSWrapper>
<div className="code-input"/>
<wljs-editor display="codemirror" type="Input" editable="true" lazy="true">{`.wlx
	
	<WLXPanel/>`}</wljs-editor>
</WLJSWrapper>

or on a slide:

<WLJSWrapper>
<div className="code-input"/>
<wljs-editor display="codemirror" type="Input" editable="true" lazy="true">{`.slide
	
	<WLXPanel/>`}</wljs-editor>
</WLJSWrapper>

Package authors can define representations for both forms with
[`MakeBoxes`](./../Formatting/MakeBoxes). See
[Decorating symbols](./../Advanced/Decorating-symbols) for custom symbolic
formatting.

## Arrange expressions

Unlike a string formatter, layout functions keep their arguments as
expressions. A row can therefore contain text, formulas, graphics, colors, or
controls at the same time.

### Rows and columns

[`Row`](./../Formatting/Row) places the elements of a list horizontally.
Strings are displayed as normal text without quotation marks:

	  {"beta", N[Pi]}

## Editable output and `Deploy`

Formatted `StandardForm` output in WLJS is usually still selectable and
editable. For example, evaluating a `TableForm` result produces a decorated
table, but its cells represent ordinary Wolfram Language expressions. You can
copy or edit the decorated result and evaluate it again as input.

This differs from the usual experience in Wolfram Mathematica. WLJS stores
visual structure as decorations over text-compatible input rather than relying
exclusively on Mathematica box expressions.

<Callout type="warning">
This is a WLJS-specific feature and does not work the same way in Wolfram
Mathematica. Mathematica copies frontend box structures or preserves formatting
wrappers; WLJS decorations can be pasted and reevaluated as ordinary list-based
Wolfram Language input.
</Callout>

## LaTeX conversion

[`TeXForm`](./../Formatting/TeXForm) exports a Wolfram expression as a LaTeX
string:

<WLJSWrapper>
<div className="code-input"/>
<wljs-editor display="codemirror" type="Input" editable="true" lazy="true">{`tex = TeXForm[Series[Sin[x], {x, 0, 7}] // Normal]`}</wljs-editor>
</WLJSWrapper>

<WLJSWrapper>
<wljs-editor display="codemirror" type="Output" lazy="true">{`"-\\\\frac{x^7}{5040}+\\\\frac{x^5}{120}-\\\\frac{x^3}{6}+x"`}</wljs-editor>
</WLJSWrapper>

`Normal` converts the truncated series object to an ordinary polynomial before
it is exported.

That string can be rendered with [`TeXView`](./../GUI/TeXView):

<WLJSWrapper>
<div className="code-input"/>
<wljs-editor display="codemirror" type="Input" editable="true" lazy="true">{`TeXView[tex]`}</wljs-editor>
</WLJSWrapper>

<WLJSWrapper>
<wljs-editor display="codemirror" type="Output" lazy="true">{`(*VB[*)(Null)(*,*)(*"1:eJxTTMoPSmNkYGAoZgESHvk5KRAeO5AISY0Iy0wtRwj4p6Xl5CdCVXACidAgH5fU5PyU1OBIIE9X1dQ5rSgxWdXcqULV1NVc1dwFyDQ1MDEAsYycUKVNIdKGRiBZNK3GEDkziL4KAIJqJTI="*)(*]VB*)`}</wljs-editor>
</WLJSWrapper>

It can also be pasted into a [Markdown](./../Cell-types/Markdown) cell:

<WLJSWrapper>
<div className="code-input"/>
<wljs-editor display="codemirror" type="Input" editable="true" lazy="true">{`.md

	$$
	-\\frac{x^7}{5040}+\\frac{x^5}{120}-\\frac{x^3}{6}+x
	$$`}</wljs-editor>
</WLJSWrapper>

Or placed directly in a LaTeX cell:

<WLJSWrapper>
<div className="code-input"/>
<wljs-editor display="codemirror" type="Input" editable="true" lazy="true">{`.latex
	
	-\\frac{x^7}{5040}+\\frac{x^5}{120}-\\frac{x^3}{6}+x`}</wljs-editor>
</WLJSWrapper>

For supported LaTeX input, `ToExpression` performs the reverse conversion:

<WLJSWrapper>
<div className="code-input"/>
<wljs-editor display="codemirror" type="Input" editable="true" lazy="true">{`ToExpression["\\\\frac{x^5}{120}-\\\\frac{x^3}{6}+x", TeXForm]`}</wljs-editor>
</WLJSWrapper>

Do not confuse `TeXForm` with `TraditionalForm`: `TraditionalForm` is an
in-notebook visual representation, while `TeXForm` produces text for
interchange with LaTeX-based tools.

<Callout type="note">
`TeXForm` is blocking. For buttons, animations, timers, and other interactive
code, use the non-blocking [`TeXFormAsync`](./../Formatting/TeXFormAsync)
variant.
</Callout>

You can also select an expression—or a sequence of expressions—and choose
**Iconize** from the context menu or the
[command palette](./Command-palette).

Small iconized values are compressed into the notebook text. Expressions larger
than 30,000 bytes are stored in the `.iconized/` directory next to the notebook
and referenced by the icon.

<Callout type="warning">
If a notebook contains file-backed icons, keep its `.iconized/` directory when
moving, sharing, or versioning the notebook.
</Callout>

Iconization changes how much source is visible, not what the expression
represents. It is useful for embedded constants and generated arguments, but
named variables or external data files are usually clearer when the same data
is reused in several places.

## When to use HTML or WLX instead

`Style`, `Grid`, and related functions are a good fit for symbolic output that
should remain close to Wolfram Language input. For a complete application page,
responsive web layout, custom CSS, or reusable interface components, use
[HTML cells](./../Cell-types/HTML) or [WLX cells](./../Cell-types/WLX).

See [Styling with HTML](./Styling-HTML) for a guided introduction. Wolfram
expressions can be embedded in those cells, and `StandardForm` can be used when
you want their ordinary WLJS output-cell appearance.

For custom formatting of your own symbolic heads, continue with
[`MakeBoxes`](./../Formatting/MakeBoxes) and the
[Decorating symbols](./../Advanced/Decorating-symbols) guide.
