
is equally valid:

```wolfram
btn = InputButton["Click"];
EventHandler[btn, Beep];

btn
```

There is also a helper symbol `Button` that allows you to assign handlers implicitly:

```wolfram
Button["Click", Beep[]]
```

### Grouping

<Callout type="tip">
If you only need visual grouping, consider using [Row](./../Formatting/Row) or [Column](./../Formatting/Column):

```wolfram
slider = InputRange[0, 1, 0.1]; 
checkbox = InputCheckbox[];

{slider, checkbox} // Column 
```

</Callout>

To group elements both visually and at the event level, use [InputGroup](./../GUI/InputGroup):

```wolfram
slider = InputRange[0, 1, 0.1]; 
checkbox = InputCheckbox[];
n = EvaluationNotebook[];

joined = InputGroup[<|"Checkbox" -> checkbox, "Slider" -> slider|>, "Label" -> "Group"];
EventHandler[joined, NotebookWrite[n, #]&]
```

It merges an association (as above) or a list of `EventObjects` into a new one. You do not need to assign separate `EventHandler`s - __just one__ `joined` handler is enough. It fires an event preserving the original structure of the association or list:

```wolfram title="Printed cell"
<|"Slider" -> 0.5, "Button" -> True|>
```

#### Joining Different Events
You can also merge event objects underlying UI elements using `Join`. Here’s a simple example:

```wolfram
button = InputButton[]
slider = InputRange[0, 1, 0.1]

EventHandler[Join[button, slider], Function[data,
  Print[data]
]];
```

You'll get either `True` or a number like `0.5`, depending on which element triggered the event. To distinguish between them, [use patterns](./../Misc/Events) (or topics):

```wolfram
button = InputButton["Topic" -> "Button"]
slider = InputRange[0, 1, 0.1, "Topic" -> "Slider"]

EventHandler[Join[button, slider], {type_ :> Function[data,
  Print[type <> ":" <> ToString[data]]
]}];
```

Or capture them individually:

```wolfram
button = InputButton["Topic" -> "Button"]
slider = InputRange[0, 1, 0.1, "Topic" -> "Slider"]

EventHandler[Join[button, slider], {
  "Button" -> Beep,
  "Slider" -> Print
}];
```

The slider prints a message; the button triggers *beep*.

#### Chaining Events
Most GUI elements support chaining, where each reuses the same `EventObject`. It’s passed as the first argument:

```wolfram
ev = EventObject[];

InputButton[ev, "Topic" -> "Button"]
InputRange[ev, 0, 1, 0.1, "Topic" -> "Slider"]

EventHandler[ev, {
  "Button" -> Beep,
  "Slider" -> Print
}];
```

With this approach, there's no need to create and join new events. This leaves a smaller footprint and reduces overhead.

## 2D Graphics
Some primitives, as well as the entire canvas, support the `EventHandler` method. Let's start with the `Graphics` expression itself.

### Graphics as an Event Generator
You can attach event handlers to a `Graphics` expression, which represents the SVG container of your 2D graph.

This approach offers some benefits over using [Primitives](#Primitives). For instance, events like `"mousemove"` or `"click"` are captured even if other objects are layered on top. The following event patterns are supported:

<Card>

- `"keydown"`: Captures keyboard input after the canvas is clicked
- `"capturekeydown"`: Same as above but also prevents page scrolling
- `"capturekeyup"`: Captures key releases and prevents the default browser action
- `"capturekeyevents"`: Captures both key presses and releases as `"DOWN:<code>"` and `"UP:<code>"`
- `"mousemove"`: Captures mouse movement
- `"mouseenter"`: Captures mouse enter position (once)
- `"mouseleft"`: Captures mouse left position (once)
- `"mouseup"`: Captures mouse up
- `"mousedown"`: Captures mouse down
- `"pointerdown"`: Captures the start of mouse, stylus, or touch input
- `"pointerup"`: Captures the end of mouse, stylus, or touch input
- `"pointermove"`: Captures mouse, stylus, or touch movement without throttling
- `"pointerrawupdate"`: Captures unthrottled, high-frequency pointer updates when supported
- `"click"`: Captures clicks (without the Alt key)
- `"altclick"`: Captures clicks with the Alt key held
- `"metaclick"`: Captures clicks with Control held, or Command on macOS
- `"shiftclick"`: Captures clicks with the Shift key held
- `"rightclick"`: Captures right click
- `"contextmenu"`: Captures right click
- `"onload"`: Fired once the canvas has loaded

</Card>

Keyboard event handlers start receiving input after the graphic is clicked and focused. `"keydown"`, `"capturekeydown"`, and `"capturekeyup"` return the browser's physical key code, such as `"KeyA"` or `"ArrowLeft"`. Use `"capturekeyevents"` when one handler needs both transitions; it returns values such as `"DOWN:KeyA"` and `"UP:KeyA"` and prevents the corresponding default browser actions.

### Pointer and digitizer input

`Graphics`, supported [graphics primitives](#primitives), and [Image](#image) accept the `"pointerdown"`, `"pointerup"`, `"pointermove"`, and `"pointerrawupdate"` patterns. They use the browser Pointer Events API, so the same handlers work with a mouse, Wacom or other stylus, touchscreen, and other digitizers exposed by the operating system.

Each pattern returns an association with the current sample:

```wolfram
<|
  "Position" -> {x, y},
  "Tilt" -> {tiltX, tiltY},
  "Pressure" -> pressure,
  "Buttons" -> buttons
|>
```

- `"Position"` uses plot coordinates for `Graphics` and its primitives. For `Image`, it uses image-canvas device pixels, including the display's device-pixel ratio.
- `"Tilt"` contains the horizontal and vertical pen angles in degrees. Devices without tilt support normally report `{0, 0}`.
- `"Pressure"` is normalized from `0` to `1`. A mouse or a device without pressure sensing may report a generic value while its primary button is held.
- `"Buttons"` is the current button bitmask. Common values are `0` for no buttons, `1` for the primary button, `2` for the secondary button, and `4` for the auxiliary button.

All four pointer patterns bypass the regular event throttle and forward every event dispatched by the browser. `"pointerrawupdate"` is intended for the lowest-latency, highest-frequency input. It can fire when position, pressure, tilt, geometry, or a chorded button changes; it does not indicate whether contact started or ended. Use the following lifecycle for drawing:

```wolfram title="Drawing lifecycle (outline)"
EventHandler[
  Graphics[primitives],
  {
    "pointerdown" -> Function[sample, beginStroke[sample]],
    "pointerrawupdate" -> Function[sample, appendSample[sample]],
    "pointerup" -> Function[sample, endStroke[sample]]
  }
]
```

Keep a `"pointerrawupdate"` handler small because it runs at the rate provided by the device and browser. Use `"pointermove"` when raw sampling is unnecessary. Browsers may still combine hardware samples internally, and `"pointerrawupdate"` availability depends on browser support and a secure browser context.

### Freehand vector drawing with mouse and stylus pressure

The following example creates a freehand vector drawing canvas from `"pointerdown"`, `"pointermove"`, and `"pointerup"` events. Each pointer press starts a new stroke, pointer movement appends coordinates while drawing is active, and pointer release ends the stroke. The `paint` flag ensures that moving the pointer without holding it down does not add points.

Every event supplies a `data` association. The example reads `data["Position"]` to build the strokes and `data["Pressure"]` to update the gauge beside the drawing area. A mouse normally reports a generic pressure value, while a compatible stylus or digitizer can report changes across the normalized range from `0` to `1`.

```wolfram
Module[{
  segments = {},
  paint = False, pressure = 0.0
},
  Row[{
    EventHandler[
      Graphics[{
        Black,
        Directive["TransitionType" -> None],
        Line[segments // Offload]
      },
        PlotRange -> 1,
        ImageSize -> {500, 500},
        "Controls" -> False
      ],
      {
        "pointerdown" -> Function[data,
          segments = Append[segments, {data["Position"]}];
          paint = True
        ],
        "pointerup" -> Function[data,
          paint = False
        ],
        "pointermove" -> Function[data,
          If[paint,
            segments[[-1]] = Append[segments[[-1]], data["Position"]];
            segments = segments
          ];
          pressure = data["Pressure"]
        ]
      }
    ] // Framed,
    VerticalGauge[pressure // Offload, {0, 1}]
  }]
] // Deploy
```

`segments` is a list of strokes, and each stroke is itself a list of coordinates. Because `Line` accepts multiple coordinate lists, all completed and active strokes can remain in a single graphics primitive. `Offload` keeps the displayed line and gauge connected to their changing values. `Directive["TransitionType" -> None]` disables coordinate interpolation for direct freehand rendering, while `"Controls" -> False` prevents the drawing gesture from panning or zooming the canvas.

This example draws vector lines with a fixed appearance, so it does not use pressure to change the strokes; the gauge only demonstrates that pressure data is being captured. For pressure-aware strokes whose width, opacity, or texture changes continuously while drawing, switch to a raster canvas and use each pressure sample while painting the pixels. That requires a different rendering workflow and is outside the scope of this example. See the [Canvas 2D API](./../Advanced/Canvas-2D/Overview) for further reading.

<Accordions>

<Accordion title="Advanced: pressure-aware raster drawing with Canvas2D">

This version uses `data["Pressure"]` to control the width of a raster stroke. The Canvas 2D context applies one line width to each subpath, so the `"pointermove"` handler finishes the current subpath and starts another whenever the pressure changes by more than the selected threshold. `AnimationFrameListener` dispatches the queued drawing commands once per animation frame.

```wolfram
Needs["Canvas2D`" -> "ctx`"];

Module[{
  canvas = ctx`Canvas2D[],
  drawing = False,
  lastPressure = 0
},
  ctx`SetFillStyle[canvas, Blend[{White, Yellow}, 0.1]];
  ctx`FillRect[canvas, {0, 0}, {500, 500}];
  ctx`Dispatch[canvas];

  EventHandler[
    Image[
      canvas,
      ImageResolution -> {500, 500},
      Epilog -> {
        EventHandler[
          AnimationFrameListener[canvas],
          Function[Null, ctx`Dispatch[canvas]]
        ]
      }
    ],
    {
      "pointerdown" -> Function[data,
        drawing = True;
        ctx`BeginPath[canvas];
        ctx`SetLineWidth[
          canvas,
          lastPressure = 10 data["Pressure"]
        ];
        ctx`MoveTo[canvas, data["Position"]]
      ],
      "pointermove" -> Function[data,
        If[drawing,
          With[{pressure = 10 data["Pressure"]},
            If[Abs[pressure - lastPressure] > 0.1,
              ctx`LineTo[canvas, data["Position"]];
              ctx`Stroke[canvas];
              ctx`BeginPath[canvas];
              ctx`SetLineWidth[canvas, pressure];
              ctx`MoveTo[canvas, data["Position"]],
              ctx`LineTo[canvas, data["Position"]];
              ctx`Stroke[canvas]
            ];
            lastPressure = pressure
          ]
        ]
      ],
      "pointerup" -> Function[data,
        drawing = False;
        ctx`Stroke[canvas]
      ]
    }
  ]
]
```

A mouse usually supplies a generic pressure value, so the stroke width may remain constant. A compatible pressure-sensitive stylus or digitizer produces the varying values used by this example.

</Accordion>

For example:

```wolfram
pt = {};
EventHandler[
  Graphics[{
    PointSize[0.05], Blue, Opacity[0.5],

```


You can do the same with [Plot](./../Plotting-Functions/Plot) and many others, since they produce a `Graphics` symbol:

```wolfram
pt = {};
EventHandler[Plot[x, {x,-1,1}, Epilog->{
  PointSize[0.05], Blue, Opacity[0.5],
  Point[pt // Offload]

```

#### Alternative Way
An alternative approach is to place the handler inside `Epilog` or `Prolog` with `Null`:

```wolfram
pt = {};
Plot[x, {x,-1,1}, Epilog->{
  PointSize[0.05], Blue, Opacity[0.5],
  Point[pt // Offload],
  EventHandler[Null, {"mousemove" -> Function[xy, pt = Append[pt, xy]]}]
}]
```

or directly:

```wolfram
pt = {};
Graphics[{
  PointSize[0.05], Blue, Opacity[0.5],
  Point[pt // Offload],
  EventHandler[Null, {"mousemove" -> Function[xy, pt = Append[pt, xy]]}]
}, PlotRange -> {{-1, 1}, {-1, 1}}]
```

When `EventHandler` sees `Null` as its argument, it internally attaches to the nearest parent. Similarly, you can attach handlers using `Epilog` or `Prolog`.

### Primitives
Certain graphic primitives also support `EventHandler`. Some supported primitives include:

- [Point](./../Graphics/Point)
- [Disk](./../Graphics/Disk)
- [Rectangle](./../Graphics/Rectangle)
- ...

They support these patterns:

<Card>

- `"drag"`: Makes the primitive draggable and returns coordinates
- `"dragsignal"`: Captures dragging without moving the primitive itself; returns coordinates
- `"dragall"`: Like `"drag"`, but also fires events at drag start and end
- `"click"`: Captures clicks without the Alt key
- `"altclick"`: Captures clicks with the Alt key
- `"metaclick"`: Captures clicks with Control held, or Command on macOS
- `"shiftclick"`: Captures clicks with the Shift key held
- `"rightclick"`: Captures right click
- `"contextmenu"`: Captures right click
- `"mousedown"`: Fires on mouse press
- `"mouseup"`: Fires on mouse release
- `"mousemove"`: Captures movement
- `"pointerdown"`: Captures the start of mouse, stylus, or touch input
- `"pointerup"`: Captures the end of mouse, stylus, or touch input
- `"pointermove"`: Captures mouse, stylus, or touch movement without throttling
- `"pointerrawupdate"`: Captures unthrottled, high-frequency pointer updates when supported
- `"mouseover"`: Captures entry into element area
- `"mouseenter"`: Captures mouse enter position (once)
- `"mouseleft"`: Captures mouse left position (once)
- `"zoom"`: Captures mouse wheel input

</Card>

For example, combining `"zoom"` and `"drag"`, you can create a widget for manually fitting Gaussian curves:

```wolfram
getGauss[x0_, A_, width_] := (
  Table[{x, A * Exp[-((x - x0)^2) / (2 * width^2)]}, {x, -1, 1, 0.01}] // Quiet
);
getGauss[{x0_, A_}, width_] := getGauss[x0, A, width];
getGauss[{x0_, A_, width_}] := getGauss[x0, A, width];
```

```wolfram
Module[{line, initial},
  initial = {-0.2, 0.8, 0.1};
  line = getGauss[initial];

  Graphics[{
    Red, PointSize[0.1],
    EventHandler[
      Point[initial[[1 ;; 2]]],
      {
        "drag" -> Function[c, initial[[1 ;; 2]] = c; line = getGauss[initial]],
        "zoom" -> Function[k, initial[[3]] = k/10.0; line = getGauss[initial]]
      }
    ],
    Cyan, Line[line // Offload]
  }, PlotRange -> {{-1, 1}, {0, 1}}, Axes -> {True, False}]
]
```

## 3D Graphics

The [Graphics3D](./../Graphics3D/Graphics3D) canvas supports these event
patterns:

<Card>

- `"click"`: Captures a click and returns the three-dimensional position on the intersected surface
- `"mousemove"`: Captures pointer movement and returns the three-dimensional position on the intersected surface

</Card>

For example, this places a sphere where you click on the plotted surface:

```wolfram
Module[{pos = {0, 0, 0}},
  EventHandler[
    Plot3D[x y, {x, -1, 1}, {y, -1, 1},
      BoxRatios -> {1, 1, 1},
      Epilog -> {Red, Sphere[pos // Offload, 0.1]}
    ],
    {"click" -> Function[point, pos = point]}
  ]
]
```

### Primitives
The following 3D primitives support `EventHandler` methods:

- [Sphere](./../Graphics3D/Sphere)

The following patterns are supported:

<Card>

- `"drag"`: Makes the object draggable, adds guide lines, and sends the coordinates

</Card>

This is especially useful for dynamic lighting. For example:

```wolfram
point = {1, 1, 1};

Graphics3D[{
  Directive["Shadows"->True],
  Polygon[{{-5, 5, -1}, {5, 5, -1}, {5, -5, -1}, {-5, -5, -1}}],
  White,
  Cuboid[{-1, -1, -1}, {1, 1, 1}],
  Directive["Shadows"->False],
  PointLight[Red, {1.5075, 4.1557, 2.6129}, "Intensity"->100],
  Directive["Shadows"->True],
  SpotLight[Cyan, point // Offload],

  EventHandler[Sphere[point, 0.1], {
    "drag" -> Function[pos, point = pos]
  }]
}, Lighting -> None]
```

This can also be applied to `Plot3D`, since it returns a `Graphics3D` expression:

```wolfram
Plot3D[Sin[x] Cos[y], {x,-10,10}, {y,-10,10}, Epilog->{
  Directive["Shadows"->True],
  SpotLight[Cyan, point // Offload],

  EventHandler[Sphere[point, 0.1], {
    "drag" -> Function[pos, point = pos]
  }]
}, Lighting -> None]
```
