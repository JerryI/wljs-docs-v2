<Callout type="warning">
Implementation differs from Wolfram Standard Library
</Callout>

```wolfram
Refresh[expr_, interval_]
```

produces a dynamic window with `expr` reevaluated each interval of time specified __in seconds__ or in `Quantity` 

```wolfram
Refresh[expr_, trigger_EventObject | trigger_String]
```

produces a dynamic window with `expr` reevaluated by `trigger` event (see [Events](../Misc/Events)).

`Refresh` has the `HoldFirst` attribute.

<Callout type="note">
`Refresh` and [Animate](../GUI/Animate) automatically reduce their update rate when an expression is too expensive to reevaluate safely. Expressions that fall back to full reevaluation are limited to 5 FPS or less, depending on expression size. The requested interval is therefore a target, not a guarantee.
</Callout>

## Example

```wolfram
Refresh[Now // TextString, 1]
```

or even for decorated symbols

```wolfram
Refresh[Now, 1]
```

## Event trigger
You can manually trigger `Refresh` using provided `trigger_EventObject`. It supports 2 patterns or event topics:

- `"Refresh"` or any other string - normal refresh
- `"FullRefresh"` full refresh bypassing JIT

Here are a few example:

```wolfram
ev = EventObject[];
Refresh[ListPlot[RandomReal[{-1,1}, {2,100}]], ev]
```

To update it normally with JIT enabled

```wolfram
EventFire[ev, True]
```

Or

```wolfram
EventFire[ev, "Refresh", True]
EventFire[ev, "I love cucumbers", True]
```

To bypass JIT and make a hard refresh (clear and rebuild)

```wolfram
EventFire[ev, "FullRefresh", True]
```

This might come handy if you need to update the plot ranges, since these are usually ignored by diff-engine and JIT.


## JIT Features
`Refresh` expression uses the same runtime optimization features as [Manipulate](../GUI/Manipulate) and [Animate](../GUI/Animate), which can benefit some cases and prevent full reevaluation.

For example:

```wolfram
Refresh[RandomImage[], 0.2]
```

or 

```wolfram
Refresh[ListLinePlot[RandomReal[{-1,1}, 100]], 0.2]
```

<Callout type="warn">
Use care with `Plot` or other expensive expressions at intervals below one second. Automatic throttling prevents unsafe update rates, but repeated full reevaluation can still create significant load. Test with a longer interval first.

Consider to use [Offload](../Interpreter/Offload) for rapidly changing data [AnimatePlot](./../Plotting-Functions/AnimatePlot) or [PlotlyExtendTraces](../Plotly/PlotlyExtendTraces).
</Callout>
