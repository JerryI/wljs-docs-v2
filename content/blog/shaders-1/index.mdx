Without a vertex shader, we don't know much about the camera position or viewpoint. However, if we define `vertexShader`, we also need to add boilerplate code that determines where the points of our mesh should be placed. This is typical in 3D applications:

> We do this by calculating where the points are in the scene by multiplying the position of the mesh in the scene (modelViewMatrix) and the position of the point. After that we multiply this value with the camera's relation to the scene (projectionMatrix) so the camera settings within THREE.js are respected by our shader. The gl_Position is the value that the GPU takes to draw our points.
> *https://dev.to/maniflames/creating-a-custom-shader-in-threejs-3bhi*

Here, we normalize `vPaperNormal` because the fragment shader linearly interpolates it between pixel coordinates. This interpolation breaks the normalization.

To make it look like gold, we can add a tinted specular highlight (which makes metal look metallic). The vertex shader stays as is, while the fragment shader also uses the half-vector between the light and viewing directions. The normal is in view space, so the viewing direction is simply `(0, 0, 1)`. Because the highlight is multiplied by the gold color, it remains gold-tinted rather than white, which is how real metals behave.
